# 고(庫)의 기본 분류

2026-11-13. 사용자는 기존 지지 자료에 고의 역할을 추가하고 크기·개고는 후속 단계로 두도록 요청했다.
별도 API 없이 원국의 `analysis.details.<pillar>.branch.storehouse`에 추가했다.

## 반환 형태

甲일간의 丑 예시:

```json
{
  "stored_element": "金",
  "role": "관성고"
}
```

- 辰戌丑未는 `stored_element`와 `role` 두 키를 가진 객체를 반환한다.
- 나머지 여덟 지지는 명시적인 `null`이다. 항상 `storehouse` 키를 제공한다.
- 지지 자체의 대표 십성과 고의 역할은 구분한다. 甲일간의 丑은 기존 대표 십성은 정재,
  저장 오행 金을 기준으로 한 역할은 관성고다.
- 고의 크기, 개고·폐고·입고 여부, 실제 재물·성과 판정 필드는 추가하지 않았다.

`stored_element`는 기존 고 모듈에 등록됐던 네 분류를 유지한다.
辰은 水, 戌은 火, 丑은 金, 未는 木이다. 土를 별도의 고에 배정하는 추가 규칙은 이번 범위에 없다.
이 분류는 현재 프로젝트의 기본 계약이며 학파별 모든 묘고·입고 규칙을 구현했다는 뜻은 아니다.

## 일간별 역할

| 일간 | 辰: 水庫 | 戌: 火庫 | 丑: 金庫 | 未: 木庫 |
| --- | --- | --- | --- | --- |
| 甲·乙 | 인성고 | 식상고 | 관성고 | 비겁고 |
| 丙·丁 | 관성고 | 비겁고 | 재고 | 인성고 |
| 戊·己 | 재고 | 인성고 | 식상고 | 관성고 |
| 庚·辛 | 식상고 | 관성고 | 비겁고 | 재고 |
| 壬·癸 | 비겁고 | 재고 | 인성고 | 식상고 |

역할은 다섯 십성군으로 제공한다.

| 기존 십성 | 고의 역할 |
| --- | --- |
| 비견·겁재 | 비겁고 |
| 식신·상관 | 식상고 |
| 편재·정재 | 재고 |
| 편관·정관 | 관성고 |
| 편인·정인 | 인성고 |

따라서 식신고·상관고를 각각 다른 역할로 반환하지 않으며 두 십성을 식상고로 묶는다.

## 기존 자료 재사용

기존 `get_transmitted_info()`가 계산한 투간·미투간 지장간의 `stem_ten_star`를 재사용한다.
저장 오행에 해당하는 지장간을 찾아 그 십성을 위 그룹으로 묶는다.
예를 들어 丑에서는 저장 오행 金에 해당하는 辛의 기존 십성을 사용한다.
辰·戌·未에서는 각각 癸·丁·乙의 기존 십성이 해당한다.
새 일간별 십성 계산표나 합·생·충 탐지기를 추가하지 않았다.

같은 지장간이 여러 천간 위치로 투출되어도 고의 역할은 하나다.
월지 여부·중복 위치·합·생·충은 기본 분류를 바꾸지 않는다.
그러한 구성은 기존 위치·관계 자료로 조회하고 크기·개고 해석은 후속 범위로 둔다.

`services/ko_analysis.py`의 기존 미구현 함수 틀은 실제 사용하는 기본 분류 함수로 정리했다.
`schemas/natal_analysis.py`의 `StorehouseInfo`는 두 필드의 값과 미등록 키를 검증한다.
`/character-details`와 `/cycle-analysis`에서도 원국 지지 노드의 `analysis.storehouse`로 같은 자료를 전달한다.
운 글자에 대한 신규 고 분석은 추가하지 않았다. 요약·관계 ID·판정 규칙과 기존 수치는 유지한다.

## 검증

- 전체 `.venv312/bin/python -m unittest discover -s tests`: **298개 통과**.
- 10일간 × 네 고 = 40개 조합의 저장 오행·역할을 고정 분류표와 대조했다.
- 다른 여덟 지지의 `null`, 본기 십성과의 구별, 반복 투간·반복 위치,
  월지·충 동반 시의 기본 분류 보존을 검사했다.
- HTTP·OpenAPI·원국 글자/운 조회에서 전달과 타입을 확인했다.
- 기존 지장간 십성 입력의 보존과 불일치 거부를 확인했다.
- 실제 달력 입력 4건의 루트 전체 응답과 원국 글자 그래프를 변경 전후 비교했다.
  `storehouse` 추가를 제외하면 기존 응답이 동일했다.

[반환 예시](storehouse_examples.json)는 합성 원국이며 실제 달력 날짜가 아니다.
기존 인덱스·요약 정리 작업을 포함해 현재 변경은 아직 커밋·푸시·환경 게시하지 않았다.
