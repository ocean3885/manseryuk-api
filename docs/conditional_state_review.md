# `conditional` 의미와 규칙 검토

**육합·삼합 후속 결정:** 두 관계 전체를 존재 정보로 통일했다. 현재는 모두
`detected`이며 아래의 조건부·억제 판정값은 변경 전 검토 기록이다.
[현행 계약](hap_presence_migration.md)을 우선한다.

**후속 결정 반영:** 이 문서는 `6b0cf25` 시점의 검토 기록이다. 이후 사용자는
자합의 성립 판단을 분리하도록 결정했다. 현재 자합은 모두 `detected`이며
주변 충·형만 기록한다. 아래 자합 상태 변경 제안과 예시의 이전 판정값은
현행 계약이 아니다. [자료 대조와 적용 결과](self_combination_source_review.md)를 우선한다.

검토일: 2026-11-13. 기준 커밋 `6b0cf25`, 실행 규칙 `2.19.0`.
작업 재개의 첫 단계로 현재 구현·주석·계약과 실제 출력을 대조했다.
판정 코드·점수·배지·자연어 생성 코드는 변경하지 않았다.

## 결론

`conditional`에는 세 가지 의미가 섞여 있다. 모두 구현 대기 상태라고 볼 수 없고,
모두 동일한 성립 조건이 구현됐다고 설명할 수도 없다.

| 대상·사유 | 확인한 사실 | 현재 코드에서 유보하는 것 | 무엇을 추가 확인하면 되는가 |
| --- | --- | --- | --- |
| 육합 `external_adjacent_clash` | 육합 구성원과 조합 바깥 지지의 인접 충 | 합·충 병존 시 육합의 최종 성립·작용 처리 | 현행 규칙에는 합·충 우선순위를 확정하는 후속 판정이 없다. 필요한 것은 별도 규칙 결정이며 임의의 추가 입력이 아니다. |
| 삼합 `duplicate_middle` | 삼합 세 종류 글자가 있고 중신이 두 위치에 존재 | 중신 중복을 완전한 삼합으로 인정할지의 규칙 해석 | 주석이 학파별 해석 차이를 이유로 보류한다. 중신 위치 탐지는 완료돼 있고 선택할 규칙 정책이 미확정이다. |
| 자합 `required_punishment_missing` | 丙戌·壬戌에 필요한 戌未 지세형이 현재 원국에 없음 | 필수 조건이 충족되지 않은 자합의 활성 | 未형의 존재 여부는 이미 검사한다. 현재 입력의 조건은 `false`로 확정돼 있으며 추가 구현을 기다리지 않는다. |

앞선 대화에서 “현재 확인된 조건에 따른 판정”이라고 한 설명은 탐지 관점에서는
맞지만, **조건을 탐지하는 구현의 완성과 그 조건을 해석하는 정책의 완결성은 다르다.**
특히 중신 중복의 `conditional`에는 규칙 해석 보류가 실제로 포함돼 있다.

## 코드와 기존 근거

### 육합

[규칙표](../services/relation_rules.py)의 주석은 “충과 합이 병존하므로 작용량을
유보”한다고 설명하지만, [탐지기](../services/branch_relations.py)는 이를
`activation_status=conditional`로 반환한다. [자연어 설명](../services/relation_presentation.py)은
육합 성립을 조건부로 둔다고 표현한다. 작용량 유보와 성립 유보의 설명 범위가 혼재한다.

[관계 규칙 문서](mangpa_relation_rulebook.md)의 육합 설명에는 기존 교재 전재본
출처가 연결돼 있다. 이번 검토는 저장소의 기록과 실행 동작을 대조한 것이며,
원문을 새로 대조해 합·충의 우선순위를 확정한 작업은 아니다.

후속 원국 입력을 자동 요청하거나 시간 경과 후 `active`로 승격하는 처리는 없다.
운 조회도 원국 판정을 그대로 보존하므로, 나중에 운을 조회하면 이 상태가 자동 해소된다고
안내하면 안 된다.

### 삼합

[규칙표](../services/relation_rules.py)에 “중신 중복은 학파별 해석 차이가 있어
보류한다”는 주석과 `duplicate_middle: conditional` 대응이 있다.
기존 [관계 규칙 문서](mangpa_relation_rulebook.md)는 중신 중복·충에 관한 출처와
프로젝트의 잠정 정책을 기록한다.

`亥卯卯未`에서는 중신 卯의 월·일 위치와 두 세 자리 조합을 모두 탐지한다.
따라서 구현에 글자 정보가 부족해서 생긴 상태는 아니다. 중신이 두 개일 때의
완전 삼합 인정 정책을 확정해야 한다. 이를 단순 입력 누락으로 설명하면 부정확하다.

### 자합

[자합 판정기](../services/relations.py)는 未형 필요와 辰충 차단을 계산한다.
丙戌·壬戌의 필수 조건과 차단 조건은 [규칙표](../services/relation_rules.py)와
[관계 규칙 문서](mangpa_relation_rulebook.md)에 명시돼 있다.

[중앙 조립기](../services/character_relation_index.py)는 다음처럼 옮긴다.

- 未형 있음·辰충 없음: `active`
- 未형 없음·辰충 없음: `conditional`, 사유 `required_punishment_missing`
- 辰충 있음: 未형 유무에 관계없이 `suppressed`, 사유 `blocked_by_chen_chung`

`is_conditional=true`는 **조건을 요구하는 규칙 유형**이다. 실제 조건 충족 여부는
`condition_met`, 현재 활성 여부는 `active`다. 未형이 충족되어도 규칙 유형은
계속 `is_conditional=true`이므로 이를 현재 상태 코드와 혼동하지 않는다.

## 실제 출력과 삭제 시 영향

아래는 일간 甲의 합성 원국이며 자합 사례만 천간 `丙甲甲甲`이다.
생년월일을 달력으로 변환한 사례가 아니라 위치를 고정한 규칙 검증 자료다.

| 지지·대상 | 현재 상태 | 사유 | 현재 매트릭스 점수 |
| --- | --- | --- | --- |
| `子丑寅辰`, 년–월 육합 | `active` | 후보 오행 안내 | 1.5 |
| `午子丑寅`, 월–일 육합 | `conditional` | 외부 인접 충 | 0 |
| `子午丑寅`, 년–일 육합 | `suppressed` | 두 합 글자 사이 인접 충 | 0 |
| `亥卯未亥`, 삼합 | `potential` | 없음 | 3.0 |
| `亥卯卯未`, 삼합 | `conditional` | 중신 중복 | 0 |
| `巳亥卯未`, 삼합 | `suppressed` | 생지 인접 충 | 0 |
| `戌子寅卯`, 년주 丙戌 자합 | `conditional` | 필수 未형 미충족 | 매트릭스 점수 대상 아님 |
| `戌未寅卯`, 년주 丙戌 자합 | `active` | 필수 未형 충족 | 매트릭스 점수 대상 아님 |
| `戌未辰卯`, 년주 丙戌 자합 | `suppressed` | 辰충 차단, 未형은 충족 | 매트릭스 점수 대상 아님 |
| `戌子辰卯`, 년주 丙戌 자합 | `suppressed` | 辰충 차단, 未형도 미충족 | 매트릭스 점수 대상 아님 |

기계 판독 가능한 발췌는 [실행 사례 JSON](conditional_state_review_examples.json)에 저장했다.

상태를 삭제하거나 다른 상태로 대응하면 다음 경로의 동작도 검토해야 한다.

- [매트릭스](../services/interaction_matrix.py): 육합은 `active`일 때만 합 점수 반영,
  삼합은 `potential`일 때만 3.0 반영. 점수는 실제 강도·피해량이 아니다.
- [기존 지지 모델](../services/branch_dynamics.py): 해당 관계의
  `conditional`·`suppressed` 잠정 방향별 작용량은 0으로 표시한다.
- [빈주](../services/bin_zhu.py): 조건부·억제 그룹의 결속 점수는 0이다.
- [내부 v3](../services/branch_dynamics_v3_assembler.py)와
  [계약 검사](../schemas/branch_dynamics_v3_contract.py): 조건부의 실제 적용량을
  확정하지 않도록 검사한다. 확인한 외부 충 육합은 `potential_calculated`와
  `applied_power_delta=null`, 억제 육합은 `resolved`와 적용량 0을 반환한다.
- [중앙 관계](../services/character_relation_index.py)·
  [응답 검사](../schemas/character_details.py)·
  [설명](../services/relation_presentation.py): 상태·사유 일치와 표시 배지를 검사한다.

따라서 `conditional`을 `active`, `potential`, `suppressed`로 일괄 바꾸는 작업은
표시 문구 정리가 아니라 판정·집계 정책 변경이다. 기존 잠정 모델을 이유로
새로운 수치화나 세력 계산을 재개할 필요는 없다.

## 권장 정리안 — 미구현 제안

새 API나 상태 필드를 늘리기 전에 현재 상태·사유·조건 근거를 활용한다.
모든 `conditional`을 `성립 유보`로 이름만 바꾸는 작업을 우선하지 않는다.

1. **자합의 미충족 조건을 먼저 정리한다.** `required_punishment_missing`은
   검사 결과가 알려진 미충족이므로 `candidate_only`로 표시하는 방안을 우선 검토한다.
   후보 자체와 필수 조건·사유는 보존한다. 이것이 외부 辰충에 의한
   `suppressed`와도 구분되며 “추후 구현 대기” 오해를 줄인다.
2. **삼합 중신 중복의 해석 정책을 확정한다.** 삼합 후보는 보존하고,
   중복 자체로 삼합 인정을 유보할지, 구성 사실과 주도·영향 미평가를 분리할지
   근거를 검토한다. 현행 정책을 바꾸면 점수 0 처리와 구성 반합 참조도 함께 확인한다.
3. **육합의 외부 충을 따로 결정한다.** 현재 사실인 합·충 병존을 보존한다.
   구조 성립을 유보하는 규칙인지, 구조는 확인하고 경합·영향만 미평가하는 규칙인지
   정한 뒤 대응 상태를 결정한다. 자동으로 `active`로 승격하지 않는다.
4. **표시와 계약을 맞춘다.** 위 결정에 따라 배지·사유 문장·계약·테스트를
   변경한다. `summary`에는 상태 반복 문구를 다시 붙이지 않는다.

위 순서의 1번이 다음 구현 후보다. 이번 검토에서는 의미와 영향 범위를
정리했고, 제안 상태로 실제 응답을 바꾸지는 않았다.

## 검증

- 대표 원국 10건: 상태·사유·설명 완결성·매트릭스 점수·관련 v3 적용량 확인.
- 육합 여섯 쌍과 외부 충·반복 글자 위치를 바꾼 조건부 방향별 행 144건:
  사유가 외부 인접 충이고 사이 충이 섞이지 않는지 확인.
- 네 삼합의 중신 중복 원국 48건: 위치별 탐지와 중앙 조회의 상태·설명 일치 확인.
- 丙戌·壬戌의 필요/차단 조건을 위치별로 바꾼 96건: 필수 조건 미충족과 辰충 차단의 우선순위 확인.
- 기존 전체 회귀 검사 250건 통과. 작업 재개 기록에도 실행 결과를 남겼다.

검사는 현행 구현의 정합성을 확인한다. 명리 규칙의 외부 원문 타당성 검증이나
실제 영향량 검증을 대신하지 않는다.
