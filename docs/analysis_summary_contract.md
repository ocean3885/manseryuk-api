# 선택 전후 비교와 구조 요약 API

갱신일: 2026-11-05. `GET /analysis-summary`는 관계 결과를 근거 ID가 연결된 설명으로 묶는다. 중요도 점수·우세·길흉·사건·손상을 추론하지 않는다. 요약 규칙 버전은 `1.2.0`, 응답 버전은 `1.0-draft`다.

## 요청

기존 필수 사주 인자 `year`, `month`, `day`, `hour`, `min`, `sl`, `gen`을 사용한다.

- 선택 인자 없음: 원국 구조 요약
- `daewoon_index=1`: 원국을 기준으로 선택 대운의 추가분 요약
- `sewoon_year=2007`: 원국+해당 대운을 기준으로 선택 세운의 추가분 요약

두 선택 인자를 동시에 주면 공통 선택 오류 400이다. 첫 대운 이전 세운은 원국과 비교한다. 날짜·시간·운 범위 오류는 기존 API와 같은 검증을 따른다.

예: `/analysis-summary?year=1995&month=5&day=12&hour=14&min=30&sl=sol&gen=남&sewoon_year=2007`.

## 응답과 비교

| 필드 | 사용법 |
| --- | --- |
| `selection` | 선택 대운·세운 정보. 원국 조회는 null |
| `comparison` | 비교 기준, 선택 소속, 추가·유지 관계 ID와 개수 |
| `overview` | 추가/유지 개수 또는 원국 구조 안내 문장 |
| `items` | 요약 ID별 카드 본문 |
| `display_order` | 화면 표시 순서대로 나열한 카드 ID |
| `character_summary_ids` | 글자별 요약 카드 참조 |
| `graph` | 원본 소속·글자·중앙 관계·범위. 카드 근거 조회에 사용 |

선택 소속이 참여한 관계는 추가, 나머지는 유지로 구분한다. 관계 ID는 기존 조립기의 안정적인 ID를 사용한다. 입력 사주 계산을 한 번만 실행한 뒤 그 그래프를 분류하므로 비교를 위해 원국을 두 번 계산하지 않는다.

현재 탐지는 새 후보를 추가하는 방식이다. 따라서 “유지”는 기록이 계속 존재한다는 뜻이며 실제 작용이 변하지 않았다는 판정이 아니다. 화면 안내도 “기존 관계도 함께 제공합니다”로 표현한다. 소멸·약화·대체 관계는 추정하지 않는다.

원국 조회의 추가 개수는 0이며 전체 관계를 유지 목록과 구조 카드로 제공한다. 운 조회의 구조 카드는 추가 관계에 집중하고, 기존 관계는 `graph` 및 동시 참여 카드에서 참조할 수 있다.

## 요약 카드

- `group`: 삼합·방합·삼형 등 다자 위치 조합
- `pair`: 관계 종류·참여 소속별로 묶은 쌍별 관계
- `transmission`: 소속별로 묶은 투간 관계
- `participation`: 한 글자가 서로 다른 종류의 여러 관계에 함께 참여하는 사실

카드에는 `title`, `description`, `character_ids`, `relation_ids`, `related_relation_ids`, `change`, `activation_statuses`, `impact_status`, `lines`, `structure_relation_ids`를 제공한다. 문장은 고정 템플릿이며 외부 LLM을 호출하지 않는다.

`lines[]`가 화면의 실제 상세 문장이다. 각 항목은 `text`, `relation_ids`, `activation_status`, `status_label`, `change`, `character_ids`, `from_character_ids`, `to_character_ids`를 갖는다. 배지는 이 항목별로 표시한다. 다자 카드는 주된 구조를 첫 줄로 두고, `structure_relation_ids`로 구성 쌍과 구분한다. 구성 쌍의 억제 상태를 삼합 자체의 상태처럼 합쳐 표시하지 않는다.

`activation_statuses`는 호환용으로 유지하는 카드 전체 근거 상태의 집합이다. 이를 카드 단일 배지로 표시하지 않는다. 원본 상태는 `graph.relations[ID].activation_status`로도 확인한다. `impact_status=not_evaluated`는 유지하지만, “미평가입니다”, “우세·경합·상쇄 판정이 아닙니다” 같은 반복 안내는 제목·설명·상세 문장에 넣지 않는다.

`participation`은 초점 글자 하나를 `character_ids`에 담는다. 나머지 상대 글자는 관계 본문에서 확인한다. 이 카드의 “함께 기록”은 관계의 경합·상쇄·강화 판정이 아니다. 운 조회에서는 이번에 추가된 관계만 묶고, 추가 관계 유형이 둘 이상인 글자만 이 카드를 만든다. 기존 관계는 `graph`와 `comparison.maintained_relation_ids`에서 확인한다.

## 중복과 순서

삼합의 반합, 삼형의 쌍형이 같은 위치 조합 안에 있으면 다자 카드에 묶는다. 방합은 현재 별도 구성 쌍 연결 규칙을 추정하지 않는다. 이 묶음은 설명 중복을 줄이는 표현 규칙이며 실제 작용의 종속·가산·억제를 판정하지 않는다.

각 추가 관계(원국 조회는 전체 관계)는 `participation` 이외의 카드 `relation_ids`에 정확히 한 번 포함한다. 여러 다자 카드가 같은 구성 쌍을 참조하면 관계 ID 정렬상 첫 카드가 본문 참조를 소유하고, 다른 카드는 `related_relation_ids`로 연결한다. 이 소유 순서는 명리적 우선순위가 아니다. 동시 참여 카드에서는 같은 근거를 다시 참조할 수 있으므로 카드별 개수를 더해 전체 관계 수를 계산하지 않는다.

반복 글자는 위치 ID로 보존한다. 카드의 주 관계(`relation_ids`)는 추가/기존을 섞지 않는다. 단, 새 다자 구조를 설명하는 기존 구성 쌍은 `related_relation_ids`로 연결한다. 이때 카드 자체는 추가 구조이며 각 `lines[].change`가 기존/추가를 구분한다. 기존 구성 쌍을 추가 개수에 포함하지 않는다. 다른 위치 조합의 다자 카드는 유지한다. 천간 쌍과 지지 쌍을 같은 종류라는 이유로 합치지 않는다. 쌍별 `lines`는 관계 하나당 한 줄로 상대 위치를 명확히 표시하고 방향 근거가 있으면 →, 없으면 ↔를 사용한다. 투간은 같은 지장간 글자·상태·출처 위치 집합을 공유하는 대상만 묶는다. 없는 출처→대상 조합을 문장이 암시하지 않도록 완전한 대응 집합만 합친다. 예를 들어 `원국 일지 寅의 지장간 丙 → 원국 월간 丙·일간 丙` 형태다. 0건 구성 쌍 안내나 카드 참조 방식 같은 구현 설명은 본문에 넣지 않는다.

명시적인 `display_order` 순서는 다자 구조 → 천간 쌍 → 지지 쌍 → 동주 천간·지지 관계 → 투간 → 글자별 요약이다. `items`도 같은 순서로 생성하지만 클라이언트는 객체 키 순서 대신 `display_order`를 사용한다. 중요도 순위가 아니다. 원국·대운·세운과 기둥 위치를 문장에 표시한다.

## 실제 결과 예

양력 1995-05-12 14:30 남성:

- 원국: 등록 관계 20건
- 대운 번호 1: 기존 20건 유지, 11건 추가
- 세운 2007: 원국+대운의 31건 유지, 세운 관련 15건 추가

세운 요약에는 원국 시지 未·대운 지지 卯·세운 지지 亥가 참여한 삼합 후보와, 원국 일지 卯·시지 未·세운 지지 亥가 참여한 별도 삼합 후보를 각각 제공한다. 합화·지원량·통근 변화는 판단하지 않는다.

## 검증

전체 관계의 추가/유지 분할과 개수, 카드 근거의 존재·누락·중복, 상태 일치, 글자별 역참조를 응답 모델에서 검사한다. 테스트는 원국·대운·세운·첫 대운 이전, 실제 다자 중첩, 원본 비변경, 입력 순서 독립성, 변조 거부, HTTP 입력 오류와 요청당 사주 계산 1회를 검증한다.

이 API는 기존 등록 관계를 요약한다. 탐지기에 없는 관계를 보완하거나 실제 명리 영향의 타당성을 검증한 결과는 아니다.

## 1.2.0 연동 예

```json
{
  "title": "추가 지지 충 1건",
  "description": "원국 연지 辰 ↔ 대운 지지 戌 — 충",
  "lines": [{
    "text": "원국 연지 辰 ↔ 대운 지지 戌 — 충",
    "relation_ids": ["해당 원본 관계 ID"],
    "activation_status": "candidate_only",
    "status_label": "후보",
    "change": "added",
    "character_ids": ["natal.chart.year.branch", "daewoon.period_1.cycle.branch"],
    "from_character_ids": [],
    "to_character_ids": []
  }],
  "impact_status": "not_evaluated"
}
```

위 예는 카드 주요 필드 발췌다. 프론트엔드는 `title`을 제목으로, `lines[].text`를 상세 내용으로, 같은 줄의 `status_label`을 배지로 표시한다. 한 줄 카드의 `description`은 첫 상세 문장과 같으므로 둘을 중복 표시하지 않는다. 표시 규칙 버전 변경으로 카드 묶음·ID는 달라질 수 있지만 원본 관계 ID·판정·추가/유지 개수는 유지된다.

## 줄별 강조와 기존 근거

줄의 `character_ids`로 선택 글자를 강조한다. 방향이 있는 관계는 `from_character_ids`, `to_character_ids`를 사용하고, 대칭 관계·다자 구조는 두 방향 목록이 비어 있다. 투간 묶음은 출처·대상이 여러 개일 수 있다. 목록은 원본 근거와 일치하는지 응답 모델이 검사한다.

`change`의 `added`는 화면에서 “추가”, `maintained`는 “기존”으로 표시한다. `mixed`는 여러 상태의 근거가 같은 줄에 포함될 경우를 위한 값이다. 카드 전체의 `change`와 보조 근거 줄의 `change`는 다를 수 있다.

예를 들어 1990-01-01 12:00 남성의 대운 번호 1에서는 원국 寅·午와 대운 戌의 삼합 후보를 설명하면서, 원국 寅↔午 반합은 “기존”, 午↔대운 戌 반합은 “추가”로 제공한다. 대운 추가 개수는 9건으로 동일하다.
