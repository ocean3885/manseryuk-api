# 출생 입력 검증과 달력 선택

`/`, `/character-details`, `/relation-index`, `/cycle-analysis`는 모두 `get_full_saju_data`의 공통 검증을 통과한다. HTTP 외의 내부 호출에도 같은 검증을 적용한다.

## 입력과 오류

| 항목 | 검증 | 오류 |
| --- | --- | --- |
| `year` | 1~9999 정수 | 범위 오류 400 |
| `month`, `day` | 정수로 변환 후 앞자리 0 정규화 | 숫자 형식 오류 400 |
| 양력 날짜 | 실제 그레고리력 날짜, 윤년 포함 | 존재하지 않는 날짜 400 |
| 음력 날짜 | 월 1~12, 일 1~30 | 범위 오류 400 |
| `hour`, `min` | 시 0~23, 분 0~59 | 범위 오류 400 |
| `sl` | `sol`, `lun`, `lun_y` | 다른 값 400 |
| `gen` | `남`, `여` | 다른 값 400 |

필수 인자 누락과 HTTP 정수 인자의 자료형 오류는 기존 FastAPI 422 응답을 유지한다. 오류 응답 형식의 전면 개편은 이번 작업에 포함하지 않는다.

숫자 범위가 유효하더라도 달력 DB에 레코드가 없으면 404다. 음력의 월별 29/30일 여부와 실제 윤달 유무는 양력 날짜 검사로 추정하지 않고 DB를 기준으로 판정한다. 예를 들어 2023년 평달 2월 30일은 존재하지만 윤2월 30일은 없으므로 후자는 404다.

## 정확한 평달·윤달 선택

DB의 `cd_leap_month`는 평달 `0`, 윤달 `1`이다. 음력은 연·월·일과 함께 이 값을 필터링한다. `lun`은 0, `lun_y`는 1만 조회하며 결과의 첫째/둘째 순서로 선택하지 않는다. 없는 윤달을 평달로 대체하지 않는다. 조건에 맞는 중복 레코드는 임의로 선택하지 않고 500으로 보고한다.

기본 응답의 `calendar.lunar.is_leap_month`는 해당 DB 레코드의 윤달 여부다.
양력 입력에서도 변환된 음력 날짜가 윤달이면 true다. 입력 `sl`로 추정하지 않는다.

실제 DB에서 2023년 평달 2월 1일은 양력 2023-02-20, 윤2월 1일은 양력 2023-03-22로 대조했다. 2024년 윤2월 요청은 404다.

## 제공 범위와 시간 규칙

현재 번들 DB의 양력 범위는 **1900-01-01~2100-12-31**이다. 음력 연도에는 양력 시작일에 대응하는 1899년 일부가 포함되며, 표시 연도가 있다는 이유만으로 해당 음력 연도 전체를 제공하는 것은 아니다. 개별 레코드의 존재를 기준으로 한다.

유효하지 않은 출생 시간을 기본 자시로 대체하던 처리를 제거했다. 정상 시간의 시지 구간은 기존 규칙을 유지한다. 예를 들어 01:30은 자시, 01:31은 축시다. 시간대·지역 보정·일주 전환 규칙을 새로 정한 작업은 아니다.

회귀 검증은 잘못된 입력의 DB 접근 전 거부, 양력 윤일, 정상 시간 양끝과 시지 전환 경계, 음력 평달/윤달, 없는 음력 날짜, DB 시작·끝 및 범위 밖, 네 API의 공통 동작을 포함한다.
