# 원국 8글자 작용 탐지 구현 현황

점검일: 2026-11-03. [이어받기 메모](./branch_dynamics_handoff.md)의 최신 우선순위에 따라 **작용 발견·성립 조건·근거 기록**만 점검했다. 세력 변화량, 피해의 타당성, 길흉은 이번 완료 판단에서 제외한다. 기존 지지 후보 78쌍의 전수 표는 [지지 후보 전수 검토](./branch_relation_candidate_audit.md)를 참조한다.

**후속 구현 기록:** 이 문서의 API 출력 현황은 점검 당시 기준이다. 이후 [8글자 관계 조회 계약](./character_relation_index_contract.md)을 실제 `GET /relation-index`로 제공했다. 아래의 개별 탐지기·규칙 지원 범위와 미지원 항목은 그대로다.

**투출·허실 후속 반영:** 2026-11-03 [조회 계약](./character_relation_index_contract.md)의 `1.3-draft`에서 지장간→천간의 위치별 투출 관계와 기존 천간 통근·허실 상태를 추가했다. 다른 기둥의 천간↔지지 **대표 오행 직접 생극**은 계속 미평가다. 투출의 정확한 지장간 글자 일치와 이를 혼동하지 않는다.

## 확인한 실행 경로

- 현행 API의 [조립 경로](../services/saju_orchestrator.py)는 [8글자별 분석](../services/analysis.py)과 [관계 매트릭스](../services/interaction_matrix.py)를 **각각** 실행하고, 매트릭스를 [지지 작용 계산기](../services/branch_dynamics.py)에 전달한다. `analysis.details`의 글자별 관계와 `advanced_analysis.interactions.matrix`는 서로 다른 출력 경로다.
- [v3 조립기](../services/branch_dynamics_v3_assembler.py)는 현재 **지지 네 글자의** 여섯 쌍·다자 구조·경합·출처 경로를 부분 함수로 조립한다. [v3 응답 모델](../schemas/branch_dynamics_v3.py)의 `stem_dynamics`는 `null`을 허용하며, v3 전체 응답은 현행 API 경로에 연결돼 있지 않다.
- [단일 규칙 파일](../services/relation_rules.py)은 지지 구조, 천간합·충·일부 극, 동주 자합 후보를 보관한다. 규칙 파일에 항목이 있는 것과 공통 출력에 위치·성립 상태·근거 ID가 있는 것은 별개다.

## 관계별 탐지·출력 현황

표의 `구현`은 현행 코드가 후보를 발견한다는 뜻이다. `부분`은 다른 출력 경로에 있거나 공통 상태·근거가 빠진 경우다. 명리 규칙의 전수 정답을 뜻하지 않는다.

| 관계 범위 | 후보 탐지와 현재 성립 판정 | 현행 출력 위치 | 1단계 판정·남은 부분 |
| --- | --- | --- | --- |
| 지지 육합 6쌍 | 위치별 탐지. 인접 충의 위치에 따라 `active / conditional / suppressed`; 합화 오행은 후보 | `interactions.matrix`, `branch_dynamics.pairwise`, v3 쌍 | **구현.** 현행 매트릭스에 조건 근거가 있음. 글자별 공통 ID 참조는 부분 |
| 지지 충 6쌍 | 거리와 무관하게 글자 존재 시 `active` | 동일 | **구현.** 실제 충격·지장간 피해 확정과 구분 |
| 지지 천 6쌍 | 글자 존재 시 `active`; 출력 용어 `천(穿)` | 동일 | **구현.** 피해 대상의 수치화는 후속 |
| 지지 파 3쌍 | 子卯·卯午·午酉, 글자 존재 시 `active`. 子卯형은 탐지하지 않음 | 동일 | **구현.** 실제 손상과 구분 |
| 쌍별 형·자형 | 丑戌·戌未은 존재 시 `active`; 辰辰·午午·酉酉·亥亥은 인접 `active`, 격위 `candidate_only` | 동일 | **구현.** 같은 글자의 반복은 v3에서 별도 `same_branch` 사실로 기록 |
| 삼형 | 寅巳申·丑戌未의 세 글자 존재 시 그룹 `active`; 구성 쌍의 충·천·합·형 상태는 유지 | 매트릭스 그룹, 지지 그룹, v3 그룹 | **구현.** 반복 지지의 실제 성립 위치 조합도 보존 |
| 삼합·방합 | 삼합 4종: 중신 중복·인접 충 조건을 판정. 방합 4종: 세 글자 존재 시 `potential` | 매트릭스 그룹, 지지 그룹, v3 그룹 | **부분.** 그룹 후보·위치는 기록하지만 방합의 세부 성립·주도 방향은 미정. `potential`을 실제 합화로 읽지 않음 |
| 반합·공합·지장간 암합 | 반합 8쌍, 공합 4쌍, 지정 암합 3쌍 후보 탐지. 완성 삼합의 내부 반합은 v3에서 구조 근거로 분리 | 매트릭스, 지지 쌍, v3 쌍 | **부분.** 공합·암합은 `candidate_only`; 반합의 독립 성립·경합 근거는 추가 판정 필요 |
| 지지 대표 오행 생·극·동기 | 여섯 위치 쌍을 검사. 구조 관계가 같은 쌍에서 `active`면 생·극을 억제. 동기는 배경 증거에 남음 | `branch_dynamics.pairwise`, v3 쌍. 원 매트릭스에는 없음 | **부분.** 생성 경로가 매트릭스와 달라 중앙 목록의 소유 주체를 정해야 함. 생·극의 오행 방향은 알지만 실제 강화·약화는 후속 |

| 천간극 | [극 탐지 함수](../services/stem_relations.py)가 규칙표에 열거된 쌍을 양쪽 방향으로 찾음 | `analysis.details[*].stem.relations.restrain` | **부분.** [공통 매트릭스](../services/interaction_matrix.py)에 함수가 import돼 있으나 호출되지 않아 중앙 관계 ID·상태·근거가 없음. 현재 규칙표에 등록된 쌍의 범위를 넘는 전수 극 판정은 이번에 확인하지 않음 |

## 글자별 조회와 근거의 실제 상태

| 점검 기준 | 현재 확인 | 완료에 필요한 작업 |
| --- | --- | --- |
| 같은 글자 반복의 위치 구분 | 지지 매트릭스의 여섯 위치 쌍과 그룹 `participants`·`formations`는 위치를 보존. 8글자 분석도 네 기둥에 천간/지지를 각각 둠 | 새 공통 참조에서도 `year/month/day/hour`와 `stem/branch`로 글자를 구별 |
| 관계 한 번 기록·글자별 조회 | 매트릭스의 쌍·그룹에는 고유 `relation_id`가 있음. `analysis.details`는 별도의 위치별 탐지를 실행하고 자체 딕셔너리를 담음 | 하나의 중앙 관계 ID를 각 참여 글자가 참조. 기존 이중 탐지 결과의 차이를 검증한 뒤 조회 뷰를 구성 |
| 성립 상태와 이유 | 지지 구조 후보에는 상태가 있으나, 천간합·충은 상태가 없고 지지 생·극/동주/자합은 서로 다른 경로에 흩어짐 | 공통 상태의 의미, 조건 근거·미판정 상태를 유형별로 명시. `active`를 실제 피해 확정으로 표시하지 않음 |
| 방향과 대상 | 지지 생·극과 잠정 子午충은 방향이 명시됨. 다른 구조 관계는 잠재 우세/역할이 있어도 실제 주도 방향은 미정. 동주 오행 관계는 지지 측 효과를 기록 | 오행상 방향·규칙상 고정 방향과 원국별 주도권을 구분. 지장간 대상이 미정이면 `null`/미정 근거로 표시 |
| 규칙·관계 참조 | 지지 v3 쌍·그룹과 중앙 `influence_paths[]`는 ID 검증이 있음. 현행 천간·동주·자합에는 동일한 참조 계약이 없음 | 새 8글자 조회의 모든 ID가 실제 중앙 관계·그룹을 가리키는지 검사. 기존 버전 ID를 섞지 않도록 명명 규칙 결정 |
| 실제 API | 현행 API는 `analysis.details`, `advanced_analysis.interactions`, `advanced_analysis.branch_dynamics`를 각각 반환 | 1단계 자료를 어디에 발행할지 계약 결정. v3는 아직 설계·부분 조립 상태이며 API가 아님 |

## 검증 근거와 한계

- Python 3.12에서 [지지 매트릭스 테스트](../tests/test_interaction_matrix.py) **16건**, [관계 규칙 테스트](../tests/test_relation_rules.py) **18건**을 실행해 모두 통과했다. 거리·중복 위치·육합 충 개입·삼형·자형·파·천·자합 후보 등을 다룬다.
- [지지 후보 전수 검토](./branch_relation_candidate_audit.md)의 78쌍·양방향 156건 불일치 0건은 **당시 규칙표와 탐지기의 일치**에 대한 기록이다. 모든 원국의 성립 조건이나 천간·동주 관계까지 전수 검증했다는 뜻이 아니다.
- `check_stem_restrain` 미호출, 천간합·충의 상태/규칙 ID 부재, 자합의 별도 출력, v3 천간 분석 `null`은 코드 경로에서 확인했다. 테스트 통과가 이 공백을 메우지 않는다.

## 권장 1단계 범위와 종료 기준

사용자가 원하는 최종 조회 단위가 **원국의 8글자 각각**이므로, 1단계의 조회 계약은 8글자를 대상으로 잡는 것을 권장한다. 첫 구현은 이미 규칙/탐지 함수가 있는 관계를 공통 목록으로 연결한다. 새로운 명리 후보의 정의와 수치화는 별도 검토한다.

1. `year/month/day/hour × stem/branch`의 8개 글자 ID를 정의하고, 중앙 관계 목록에는 각 위치 쌍/그룹/동주 관계를 한 번만 기록한다. 참여 글자별 ID 목록은 중앙 목록의 참조로 만든다.
2. 지지 여섯 쌍과 삼합·방합·삼형, 천간 여섯 쌍의 합·충·**현재 규칙표에 있는 극**, 동주 오행 관계·자합을 함께 연결한다. 현재 지지 생·극은 매트릭스 밖에서 생성되므로 중앙 목록 생성 원천을 명확히 한다.
3. 후보/성립/조건부/억제/미판정의 의미와 근거를 유형별로 정의하고, 천간·동주에도 상태를 부여한다. 실제 강화·약화·손상량은 계산하지 않는다.
4. 반복 글자와 다자 구조에서 ID 중복·누락이 없고 모든 글자별 참조가 유효하며, 성립 상태를 글자별로 임의 복제하지 않음을 자동 검증한다.
5. **완료라고 부를 범위**는 위에서 합의한 탐지 유형과 원국 입력이다. 천간 간 生·동기, 다른 기둥의 천간↔지지 직접 관계, 특정 지장간 피해·入墓는 규칙·탐지 범위 결정이 필요하므로 현재 자동 완료 항목으로 숨기지 않는다.

**다음 구현 단위:** 수치 모듈에 손대기 전에 8글자 중앙 관계·글자별 참조의 최소 출력 계약을 만든다. 천간극·동주 자합을 현행 경로에서 잃지 않도록 데이터 흐름을 설계하고, 지지 v3와 현행 API 중 어떤 경로에 먼저 연결할지 결정한다.
