# 응답 문구와 고·지장간·투간 연결 검토 — 2026-11-14

## 결과

현행 응답 경로의 설명·요약·상징 해석을 점검하고 두 종류의 문구를 수정했다.
고·지장간·투간은 현재 필드와 중앙 관계로 연결 가능하며, 조사 표본에서 누락이나 불일치는 없었다.
새 해설·LLM 호출·고 크기·개고 판정·API 필드는 추가하지 않았다.

## 과도하게 읽힐 수 있는 문구 수정

| 위치 | 기존 | 변경과 이유 |
| --- | --- | --- |
| 동주 허투의 `meaning` | 계산상 통근 없이 천간에 드러난 상징 | 동주 지지에는 통근이 없으며 타주 지원은 별도 확인한다고 명시. 동주 무근을 원국 전체의 무근으로 확대하지 않는다 |
| `ai_consultation_prompts`의 신살·관계 제목 | 주요 신살 및 길신 / 주요 상호작용 | 목록 중 최대 3개·중요도 순위 아님. 실제 선택은 단순 앞 3개이며 중요도 계산이 없다 |

키·자료형·상태·선택 항목과 순서는 유지한다. 해당 제목 문자열 자체를 파싱하는 소비자는 변경을 확인해야 한다.
이 필드는 기존 API가 반환하는 상담 참고 문자열이며 외부 LLM을 호출하는 기능이 아니다.

점검한 나머지 현행 경로:

- `analysis` 요약·`interaction_matrix`: 관계 존재·구성·상태를 기술한다. 육합·삼합은 후보/조합으로 표시한다.
- `relation_presentation`: 생·극 방향과 투간 일치를 설명하고 탐지·성립·실제 영향을 구분한다.
- `five_elements`: 8글자의 개수 분포와 잠정 지표임을 이미 명시한다.
- `special_stars`: 전통적 상징·탐지 기준을 제공한다. 개인의 능력·사건 검증을 뜻하지 않는다.
- `bin_zhu`: 기존 관계 구성만 연결하며 점수·성과를 판정하지 않는다.
- `xu_shi`: 전통적 상징 참고와 실제 능력·성과를 구분한다. 위 동주 허투 범위는 보완했다.

미사용 주석·보존된 실험 v3·과거 전주 통근 비교 모듈의 문구를 현행 출력으로 간주하지 않았다.
이번 검토는 과도한 서술과 현행 코드 계약의 정합성 점검이며 명리 규칙 자체의 학술적 타당성 검증은 아니다.

## 고에서 실제 투간 대상까지 읽는 순서

1. `analysis.details.<pillar>.branch.storehouse.stored_element`로 저장 오행을 확인한다.
2. 같은 branch의 `transmitted`와 `hidden`에서 저장 오행에 해당하는 지장간을 찾는다.
   현재 분류는 辰→癸(水), 戌→丁(火), 丑→辛(金), 未→乙(木)이다.
3. 해당 항목의 `stem_ten_star`를 십성군으로 묶은 값이 `storehouse.role`이다.
   지지 본기의 십성이나 `transmitted.from_ten_star`로 고 역할을 정하지 않는다.
4. `transmitted`이면 `stem_idx`(0 년·1 월·2 일·3 시)로 실제 천간 위치를 찾는다.
   `from_idx`는 지장간을 포함하는 지지 위치다. 반복 투간은 대상 위치마다 한 행이다.
5. `hidden`이면 같은 지장간 글자가 원국 천간에 없다는 뜻이다. 비활성·폐고·무효를 뜻하지 않는다.
6. `/character-details`의 해당 지지 노드는 같은 `analysis`를 가진다.
   중앙 관계의 `type=transmission`, `hidden_stem`, `direction.from_character/to_character`로
   지지→천간 위치를 연결한다. `/cycle-analysis`에서도 원국 노드와 관계를 보존한다.

`jijanggan`은 전체 지장간 글자 목록이고, `transmitted`/`hidden`은 그 목록을 실제 천간 일치 여부로 나눈 것이다.
관계의 탐지는 지장간의 실제 세력·고의 개방·재물 발생을 판정하지 않는다.
현재 `storehouse`에는 참여 지장간을 가리키는 직접 참조 필드가 없지만 기존 목록으로 추적 가능하다.
현행 저장 오행 매핑은 코드 계약이므로, 추후 화면이 필요하다면 이 계약을 이용하는 표시 방식을 먼저 검토한다.
운 글자의 신규 고 분석이나 고의 크기·개고는 구현하지 않았다.

## 실제 응답 사례

[추출 JSON](response_wording_storehouse_examples.json)에 요청·기둥·전체 지장간·투간·미투간·관계 참조를 저장했다.

| 출생 요청 | 기둥 | 고 역할의 근거 | 투간 연결 |
| --- | --- | --- | --- |
| 양력 1995-05-12 14:30 남 | 시지 未 | 木→乙(식신)→식상고 | 乙이 년간에 투간. 未 본기의 己는 편관으로 고 역할과 다름 |
| 양력 1990-01-08 18:00 남 | 월지 丑 | 金→辛(편인)→인성고 | 辛이 시간에 투간. 丑 본기의 己는 편관 |
| 양력 2000-02-29 23:59 남 | 년지 辰 | 水→癸(편관)→관성고 | 癸는 미투간. 戊가 월간에 투간하더라도 고 역할은 戊로 바뀌지 않음 |

실제 표본의 고는 3건으로 戌 사례와 반복 투간을 모두 포함하지 않는다.
기존 `test_storehouse.py`의 10일간×4고=40조합, 반복 투간·충 동반·본기 구별 검사로 그 범위를 보완한다.

## 검증

- 실제 출생 입력 6건 × 루트·글자·관계·대운 선택 조회 = 24개 HTTP 응답 확인.
- 전체 지장간과 투간/미투간 목록의 일치, 고 3건의 역할 근거, 투간 관계 33건의 글자·방향·대상 위치 일치 확인.
- 루트·글자 조회·운 조회의 원국 branch 분석이 동일함을 확인.
- HEAD의 변경 전 모듈과 변경 후 응답 비교: 39개 문자열 값만 변경. 키·배열 길이·수치·판정·관계 참조는 동일.
- 전체 `.venv312/bin/python -m unittest discover -s tests`: **346개 통과**.
  기존 AnyIO 스트림 ResourceWarning이 있었으나 실패는 없었다.
- 새 회귀 사례는 동주 무근이면서 타주 지원이 있는 원국에서 의미 설명의 범위를 확인한다.

프로젝트 가상환경이 없어 Python 3.12로 `.venv312`를 만들고 기존 requirements.txt를 설치했다.
커밋·푸시·환경 게시는 수행하지 않았다.
