# 글자별 간결 표시 계약

2026-11-14. `/character-details`와 `/cycle-analysis`의 모든 `characters[ID]`에
`display`를 추가했다. 새 엔드포인트·인증 키·LLM 호출은 필요 없다.
기본 `/`와 `/relation-index`에는 추가하지 않았다.

## 프론트엔드 전달 지침

1. 원국 상세는 `/character-details`, 대운·세운 선택 후 상세는 `/cycle-analysis`를 요청한다.
2. 선택한 글자의 `display.title`, `subtitle`을 그대로 표시한다.
3. `relation_groups`를 받은 순서대로 순회해 그룹 `title`, 각 항목 `text`를 표시한다.
4. `sections`도 같은 방식으로 표시한다. 통근·고·지장간·기둥 정보의 문구가 완성돼 있다.
5. 항목의 `detail_lines`가 있으면 펼침으로 표시할 수 있다. 없으면 펼침을 생략한다.
6. 클릭 연결은 `character_ids`, 관계 상세 연결은 `relation_ids`를 사용한다.
   배열은 모두 보존한다. 여러 상대·관계가 있으면 하나만 임의 선택하지 않는다.
7. 운 선택이 바뀌면 응답의 모든 글자를 교체한다. 원국 글자의 display도 함께 달라진다.
8. 빈 그룹·섹션 배열은 생략한다. 비어 있다는 이유로 미평가 항목을 ‘없음’으로 만들지 않는다.

문구 조합·소속 분류·관계명 변환·방향 계산·중복 병합은 프론트엔드에서 다시 하지 않는다.
배치·색상·선택·펼침과 클릭 동작은 프론트엔드가 담당한다.
원국 표·운 선택 목록은 기존 루트 응답을 사용한다.

## 구조

```json
{
  "version": "1.0.0",
  "title": "원국 시지 未",
  "subtitle": "토 · 음 · 편관",
  "relation_groups": [
    {
      "key": "sewoon.year_2026",
      "title": "세운 2026 丙午",
      "items": [
        {
          "text": "지지 午 · 육합 · 생 ←",
          "character_ids": ["sewoon.year_2026.cycle.branch"],
          "relation_ids": ["해당 육합 ID", "해당 생 ID"],
          "detail_lines": ["세운 지지 午 → 원국 시지 未"]
        }
      ]
    }
  ],
  "sections": []
}
```

위 JSON은 구조 설명용 축약 예시다. 실제 12글자의 전체 출력은
[실제 표시 예시](character_display_example.json)에 있다.
표시 전용 버전은 `display.version=1.0.0`이고 기존 그래프 버전은 유지한다.
공통 모델의 display는 과거 합성 계약 자료와 호환되도록 nullable 기본값을 허용하지만,
현재 두 API의 생산 응답에는 모든 글자에 객체를 제공한다.

## 관계 목록 규칙

- 원국·대운·세운·복합 관계 순으로 표시한다. 소속 그룹 key는 context ID, 복합 그룹은 `mixed`다.
- 선택 글자를 제외한 상대가 모두 같은 소속이면 그 소속 그룹에 넣는다.
  상대가 여러 소속이면 복합 관계로 넣고 각 상대에 소속명도 표시한다.
- 상대는 원국 년·월·일·시, 같은 위치 천간·지지 순이다. 동일 상대 집합의 여러 관계를 한 행에 묶는다.
  관계명 순서는 고정된 관계 type/ID 순이며 중요도·길흉 순위가 아니다.
- 각 글자의 원래 relation_ids가 표시 항목에 정확히 한 번씩 포함된다.
  같은 관계가 참여 글자 각각의 목록에 보이는 것은 정상이다.
- 다자 관계는 선택 글자를 뺀 나머지 참여자를 `+`로 나열한다. 실제 위치 조합은 detail_lines에 보존한다.
- 생·극·투간과 방향이 있는 동주 오행 관계만 화살표를 표시한다.
  `→`는 선택 글자가 출발점, `←`는 상대가 출발점이다. 합·충·형 등의 목록 순서를 방향으로 해석하지 않는다.
- 천간합과 육합은 구분하고, 동일 오행의 동주 관계는 `동오행`으로 표시한다.
- `후보`, `통근 미평가`, `관계 영향 미평가`, 상태·등록 조합·평가 범위 안내는 display에서 생략한다.
  기존 activation_status·coverage·presentation은 그대로 남으며 상태를 성립으로 바꾸지 않는다.

## 추가 정보 규칙

- 원국 천간: 동주 통근 유무, 실제로 기록된 타주 지원 위치를 표시한다. 운 천간에는 통근 안내를 만들지 않는다.
- 지지: 기존 지장간·십성과 같은 글자의 투간 대상 위치를 표시한다.
  원국 지장간에 표시된 `원국 미투간`은 원국 천간에 같은 글자가 없다는 뜻이며 폐고·무효 판정이 아니다.
  선택 운에 같은 천간이 생기면 해당 투간 연결도 함께 표시한다.
- 고: 저장 오행·역할과 그 근거 지장간 십성을 표시한다. 실제 투간 대상은 별도 연결한다.
  크기·개고·재물 발생을 추론하지 않는다.
- 운 지지의 지장간도 제공하지만 운 한 기둥 내부 투간·고·통근 판정은 새로 만들지 않는다.
- 운성·신살은 기존 기둥 정보로 지지 패널에 한 번 표시한다.
- 새 정보가 없는 관계의 설명은 만들지 않는다. detail_lines는 방향·지장간·위치 조합 등 구체적인 사실만 담는다.

## 검증

원국 8·대운 10·세운 12글자의 HTTP 출력, 첫 대운 이전, 선택 변경,
모든 관계 ID의 정확한 표시, 방향 반전, 동일 상대 병합, 반복 글자의 다른 위치,
다자 위치 조합, 고 근거, 원본 비변경과 재조립 멱등성을 검사한다.
실제 출생 6건의 원국·대운 10·세운 100, 총 666개 그래프에서도 모든 글자에 표시를 제공하고
관계 누락·중복·잘못된 상대 연결이 없음을 확인했다.
기존 24개 HTTP 응답 비교에서 display를 제외한 원자료는 동일했다.
전체 352개 테스트 통과. 프론트엔드 화면 자체와 실제 렌더링 크기는 아직 확인하지 않았다.
